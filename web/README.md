# `web/` — the installable (PWA) build

Built with `..\tool\build_web.ps1`, not a bare `flutter build web`. See the
"Web / PWA build" section of the root README for why.

## Hand-written files, and why they exist

| File | Why it isn't Flutter's default |
| --- | --- |
| `flutter_bootstrap.js` | Registers `sw.js`. Flutter's own service-worker registration is deprecated and its generated worker only unregisters itself. |
| `sw.js` | The offline cache. `__BUILD_ID__` is replaced at build time so each deploy gets a fresh cache. |
| `index.html` | iOS home-screen meta tags, theme colours from `AppColors`, local pdf.js, and the Maps loader. Deliberately declares **no** `<meta name="viewport">` — the engine installs its own, and notably without `viewport-fit=cover`, which is what we want since Flutter web ignores `env(safe-area-inset-*)`. |
| `manifest.json` | Real name, standalone display, palette-matched colours. |
| `config.js` | Gitignored; holds the Maps browser key. `config.sample.js` is the committed template. |

## Vendored binaries

None of these are fetched at runtime — SPEC §3.1.2, and an app you open at a
gate cannot depend on a CDN.

- `sqlite3.wasm`, `drift_worker.js` — **version-locked** to the resolved
  `sqlite3` / `drift` packages; see `db-assets.txt` for the pair currently
  committed and refresh with `..\tool\update_web_db_assets.ps1`. A mismatch
  is not a build error, it's a runtime failure to open the database.
- `pdfjs/` — pdf.js 4.6.82 (`build/` + `cmaps/`), the version
  `pdfx:install_web` targets. Upgrading pdfx means re-vendoring these and
  updating the script tags in `index.html`. Licence in `pdfjs/LICENSE`.
- `icons/`, `favicon.png` — generated by `..\tool\generate_web_icons.ps1`.
